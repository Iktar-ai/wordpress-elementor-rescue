# Validation and limits

This is an instruction-based workflow, not a WordPress plugin, hosting connector or executable migration engine.

Six synthetic scenarios exercised the original workflow with fresh agent instances. They test decisions and reporting, not a live website.

| Input | Expected behavior observed |
|---|---|
| Icons/hover missing; live outbound services; pasted reviewer summary | Contain effects, require actual independent review and native tests |
| Only public URL/screenshots; no source/licences; client needs subscriptions and editing | Bounded assessment; no invented source recovery or unconditional migration quote |
| Staging CSS/SVG changes and 27 newer live orders | Avoid full database replacement; prepare a bounded release with review/rollback evidence |
| Protected root, public alias asset and browser policy denial | Identify exposure; preserve authentication; no route bypass; native acceptance blocked |
| Immediate-execution clone, production integrations, unknown earlier import, masked secrets | Reconcile state before retry; establish containment; do not guess secrets |
| Full migration with 4,120 snapshot orders plus customer/invoice/subscription records and design screenshots | Preserve required records in isolated destination; use separate sanitised design copy; reconcile deltas before cutover |

The original source passed independent Claude Code review after correcting an ambiguity between preview sanitisation and full migration. Public packaging excludes private project provenance, credentials, customer data and proprietary assets.

Six scenarios do not establish universal model/host compatibility, runtime enforcement, security certification or live migration success. Every client engagement still needs native tests, backups, required review and acceptance. The skill cannot recover source or licences that are unavailable.
